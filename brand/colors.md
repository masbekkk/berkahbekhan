# Brand Colors — berkahbekhan.inc

The color system for **@berkahbekhan.inc** balances systemic brand consistency with individual project personality.

> **CORE PRINCIPLE**: Do NOT force every project into the same color palette. Project screenshots must retain their own authentic visual identity and interface colors. The BerkahBekhan brand provides consistency through typography, spacing, composition, and labeling.

---

## 1. Flexible Canvas Backgrounds

**Dark mode is NOT mandatory.** Choose the canvas background that best flatters and frames the real product UI:

| Canvas Style | Hex Value | Best Used For |
| :--- | :--- | :--- |
| **Deep Dark (Obsidian)** | `#0B0F14` or `#0F172A` | High-contrast showcase of dark-themed apps, code panels, and terminal outputs. |
| **Editorial Light** | `#F8FAFC` or `#F1F5F9` | Clean, modern magazine-style showcase of light-themed dashboards and SaaS apps. |
| **Neutral Slate / Zinc** | `#18181B` or `#1E293B` | Technical deep dives, database topologies, and subtle system diagrams. |
| **Project-Derived** | *Sampled from UI* | An ultra-subtle tint sampled from the application's dominant background or brand tone. |

## 3. Usage & Anti-Slop Rules

1. **Let Product UI Dominate**: If an application interface features green, amber, or purple brand tones, let those colors live naturally in the screenshot. Do not attempt to recolor or tint the product UI.
2. **Restrained Accents**: Brand accent colors should occupy no more than 5% of the canvas surface area. Accents are for mono badges or single focal keywords, never for giant background washes.
3. **No Neon Gradients**: Avoid bright rainbow gradients, neon glows, and multi-color gradient meshes behind cards.
4. **No Double-Boxing**: Never place a dark screenshot card inside another dark card container. Keep containers flat and intentional.
